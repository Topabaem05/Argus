Argus Mini‑Bot Fixes & Persona Simulation
Enhancement – Detailed Plan
Overview
This plan addresses two key objectives for the Argus repository:


    1. Fix mini‑bot animation issues and navigation – adjust humanoid rigs, animation controllers and
       navigation settings so that actions like running, turning and idle look natural and the character
       can move freely in the schoolroom without sliding or colliding with walls.
    2. Extend Argus with persona‑driven simulations – build a system that selects up to 20 personas
       from a corpus of ~10 000 personas, uses chat or uploaded files to evaluate the content with an
       external NVIDIA NLP model, maps the results back into selected personas, then runs an in‑world
       discussion among the mini‑bots. The system should allow optional persona updates (with dataset
       backups) and follow rendering guidelines similar to MuJoCo, using URP Simple Lit materials and
       a procedural floor grid.

The sections below outline step‑by‑step tasks for diagnosing the animation/rigging problems, updating
rendering, designing the persona chat pipeline and providing skeleton code for new features.


1. Diagnose and Correct Mini‑Bot Animations

       attention to the orientation of the hips/root bone.

    3. Apply root‑motion properly: In the Animation tab for each clip:


    4. Enable Root Motion and set the Root Transform Position to XZ and Root Transform Rotation

    5. If the clip does not include rotation (e.g., Turn animations), set Root Transform Rotation
       to Original so the Animator can rotate the object programmatically.

2. Rendering and Environment Setup (MuJoCo‑style)

2.1 Use URP/Simple Lit materials

Unity’s URP offers a Simple shading model which is based on the Blinn‑Phong approach, suitable for
stylized visuals and devices where physically based rendering is unnecessary 1 . To match the MuJoCo
look:


      1. Replace PBR materials: Assign URP/Simple Lit to the mini‑bot and environment materials.
         Remove all texture maps and set a pure base color (e.g., saturated red or blue). Enable Specular
         Highlights and set Smoothness between 0.5–0.7 so only the lit areas show sharp specular
         highlights.
      2. Uniform lighting: Under Window → Rendering → Lighting, change Environment Lighting
         Source to Color and choose a neutral light grey (flat grey). This removes skybox reflections and
         prevents the underside of objects from becoming pitch black.
      3. Directional light: Use a single directional light with Hard Shadows or slightly softened shadows;
         disable all post‑processing (Bloom, Color Grading, Ambient Occlusion). Enable only MSAA to
         reduce aliasing. This configuration mimics the clean look of MuJoCo.
      4. Procedural floor grid: Create a Shader Graph for a procedural grid. Use the UV coordinates in
         world space, apply frac() to achieve repeating lines and mix the result with base colour. The
        grid remains crisp regardless of camera zoom.

4.4 PersonaConversationManager.cs


 using System.Collections.Generic;
 using System.Threading.Tasks;
 using UnityEngine;


 public class PersonaConversationManager : MonoBehaviour {
     public List<MiniBotPersona> bots;
     public int maxTurns = 3;


     public async Task StartDiscussionAsync(string initialMessage) {
         // broadcast initial message
         foreach (var bot in bots) {
             await bot.RespondToAsync(initialMessage);
         }
         // round‑robin discussion
         for (int turn = 0; turn < maxTurns; turn++) {
             foreach (var bot in bots) {
                 // pick another bot to speak to
                 var target = bots[Random.Range(0, bots.Count)];
                 string thought = $"What do you think, {target.persona.name}?";
                 await bot.RespondToAsync(thought);
             }
         }
         // end of discussion: update persona memories if needed
     }
 }

5. ReAct‑style Execution
The ReAct (Reasoning and Acting) approach suggests iterative cycles:


          1. Reasoning: Inspect the current mini‑bot setup (rig, animations, navigation) and hypothesize
             causes for issues. Verify assumptions by playing the scene.
          2. Acting: Modify the rig import settings, fix the animator controller and run the scene again. Repeat
             until the mini‑bot’s running and turning appear natural and the bot navigates correctly.
          3. Reasoning: Design the persona selection and simulation pipeline. Decide on data structures, API
             calls and concurrency model.
          4. Acting: Implement skeleton scripts ( PersonaSelector , MiniBotPersona ,
                 PersonaConversationManager ) and connect them to the Unity UI. Use placeholder code for
             external API calls. Test with a small subset of personas and simple chat messages.
          5. Reasoning: Evaluate the simulation’s behaviour: do bots adopt different opinions? Does the
             environment lighting match MuJoCo’s style? Are grid lines crisp at all scales?
          6. Acting: Tweak parameters (blend tree thresholds, lighting colours, grid cell size) until the
             experience feels cohesive.

By following this plan, Argus will deliver smooth mini‑bot animations, visually consistent URP rendering,
and a robust persona‑driven chat simulation capable of dynamic discussions and persona updates.
